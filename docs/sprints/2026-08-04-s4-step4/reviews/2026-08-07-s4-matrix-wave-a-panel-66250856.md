### Consolidated must-fix (fold at the pair under REVIEW-FOLD; FOLD_SCOPE before any edit)

M1 — **The git wrapper's env pinning is both too broad and too permissive (git.cpp).** Correctness #1 (E2, reproduced against git 2.50.1): `GIT_CONFIG_GLOBAL=/dev/null` is pinned on EVERY invocation, but D1.1 scopes the isolated global config to restore-side only; on the pack side it suppresses the user's `core.excludesFile`, so a globally-ignored file trips the D2.2 dirt gate and a clean repo is refused `RepoDirtyUnsupported`. Security #2 (E1): repo-local `.git/config` (`core.hooksPath`, `credential.helper`, `core.sshCommand`) stays fully in force under `-C <untrusted repo>`. Together: move the isolated global config to restore-side `Opts`, let classification read user global excludes, and neutralize the repo-local keys via `GIT_CONFIG_COUNT`; the T2 "env is pinned" test locks the current over-broad scope and must move with the fix.

M2 — **The `--` delimiter is not mechanical at the engine call sites (security #4, correctness #7; E1/E2).** Value-typed strings ride the option side: bundle output paths and `^<base>` revisions in capture, and manifest-supplied ref/branch/sha names in restore (`show-ref`, `update-ref`, `checkout --detach`, `reset --hard`). Revisions genuinely cannot go after `--`, so the required control is VALIDATION at the type boundary (object names hex-only; ref names against check-ref-format), not delimiting. This contradicts the plan's R5 "mechanically inserts `--`" acceptance bar. (Correctness confirmed `--` IS accepted by every subcommand the wrapper does apply it to.)

M3 — **Restore path containment is missing (security #3; E1).** `partial_root / entry.relpath` (restore.cpp:360, and `stage_root / *entry.bundle`) has no containment check; an absolute or `..`-bearing manifest relpath escapes the root before the post-hoc canonical assert fires, directing `mkdir`/`clone`/`unbundle` out of tree. Reject non-relative/non-normalizing relpath/bundle/local_refs_bundle inside `restore_entry` before any mkdir or spawn, with a hostile-manifest test.

M4 — **No engine call sets a per-call budget; the 30s default is unmet by design (performance #2, correctness #8; E1).** `bundle create --all`, `clone`, `unbundle`, and network `ls-remote`/`fetch` all inherit 30s; D1.1 introduced per-call budgets precisely because bundle creation is minutes-class. A large repo times out and mislabels as `GitInvocationFailed`. Give each call class its own budget and distinguish budget-expiry from git-failure in the error kind.

M5 — **Eligibility is O(refs x tips) subprocesses (performance #1; E1 structure, E2 timing ~21.8ms/pair).** `check_ancestry` spawns up to two git processes per (ref, tip) and is re-entered per local ref; the unprovable-branch worst case is the common case. Hoist the per-tip `cat-file -e` presence pass out of the per-ref loop and use one `rev-list --not <tips>` filter per ref to make it O(refs + tips); bound the tip-list size with an explicit over-threshold result.

M6 — **The promisor PRE-STEP policy does not propagate (correctness #3, tests #2; E1/E0).** `Classification::promisor` has no reader outside classify.cpp; eligibility and capture each re-derive the predicate from live config at their own call time, and only capture maps a missing-object failure to `PromisorObjectsUnavailable` while classify/eligibility fold every failure into `git_invocation_failed` — but D2.2 says "ANY of those invocations." The property `GIT_NO_LAZY_FETCH=1 on every promisor invocation` is asserted by NO test (tests #2). Thread the classification-time bit onto `RepoEntry`; one predicate, one missing-object mapping; assert it via a request-trace seam.

M7 — **The restore divergence vocabulary is unproducible; two dead fields shaped to carry it (correctness #5; E1).** `RepoRestoreOutcome::failed` is never assigned and `LocalRefRestoreRow::detail` never written — every per-ref failure and verification mismatch returns `RepoRestoreFailed` (exit 4), but D5.2/D5.3 place `local-ref-failed` and `repo-verify-divergence` in the WARNING class (exit 2). Return the row with per-ref detail and a divergence outcome instead of aborting the entry.

M8 — **`RefUncapturable` and promisor `verify_bundle` are mis-mapped (correctness #2, #4; E1).** `RefUncapturable` is emitted for a bundle-create process failure with no `ref` in facts, though D5.1 fixes `{repo_relpath, ref}` and the genuine per-ref neither-route condition is never computed; and any non-zero `bundle verify` on a promisor repo maps to `PromisorObjectsUnavailable` (a corrupt bundle reads as a promisor refusal) instead of gating on `missing_object_failure` like the create paths do.

M9 — **The comparator carries a second, code-only tolerance surface (correctness #9; E1).** `_tracked_paths` silently exempts git-tracked files from `file-mtime`, and `_entries` excludes all `.git` paths for every scenario — real exemptions, but not declared tolerance rows, against D6's "tolerance stays the single source" and the T3 acceptance bar. Express both as declared tolerance rows the comparator reads.

M10 — **Tests assert their fixtures, not the units (tests #1, #3, #4; E1).** The "full environment / no parent passthrough" test only asserts one var is visible and cannot fail on a parent-passthrough regression (the whole T2 isolation story rests on it); the "eligibility is optional" test round-trips `std::optional`'s copy constructor with a name promising a classify round-trip; cap saturation has no test on either stream and a truncated `ls-files -s/-u` would drop the gitlink/conflict that raises a fence. ### === LENS 3/5: performance ===

Lens: performance
Verdict: must-fix

Findings:
1. must-fix `src/core/repo/eligibility.cpp:138-165` (loop) and `:261-275` (caller) — `check_ancestry` walks every advertised tip and spawns up to two git processes per tip (`cat-file -e` at :147, `merge-base --is-ancestor` at :158), and it is re-entered once per local ref at :267. Cost is O(refs × tips) processes, and the worst case is the common case: a local branch that is provable exits early, while an unprovable work-in-progress branch scans the full tip list. Measured on this host against this repo, `cat-file -e` costs 10.8 ms and `merge-base --is-ancestor` 11.0 ms, so ~21.8 ms per (ref, tip) pair — 20 refs against 200 tips is ~87 s, 50 refs against 500 tips is ~544 s, for a single repo.
